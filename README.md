# OrangeHRM – Manual & Automation Testing

A QA portfolio project focused on manual and automated testing of the OrangeHRM Demo application using Java, Selenium WebDriver, TestNG, and the Page Object Model (POM) design pattern.

## Project Overview

The main goal of this project is to evaluate the functionality and user interface of the OrangeHRM application, identify potential issues, and verify that its core features work as expected.

Both manual and automation testing approaches were used throughout the project.

**Application Under Test:** [OrangeHRM Demo](https://opensource-demo.orangehrmlive.com/)

## Testing Scope

The project covers four main application modules.

### 1. Login Module
- Successful login with valid credentials
- Login with invalid username
- Login with invalid password
- Validation of empty username and password fields
- Login using the Enter key

### 2. Dashboard Module
- Dashboard page loading
- Dashboard heading verification
- Navigation to PIM and Admin modules
- Profile menu verification
- Logout functionality

### 3. PIM Module
- PIM page loading and heading verification
- Employee search with valid and invalid names
- Adding a new employee
- Uploading an employee profile picture
- Editing employee information
- Deleting an employee
- Required field validation

### 4. Admin Module
- Admin page loading and heading verification
- User list verification
- Search by username
- Search by user role
- Search by status
- Reset search filters

## Automation Framework

The automation framework is implemented using the Page Object Model (POM) design pattern.

The framework separates page elements, test scenarios, browser management, and reporting functionality.

**Main components:**
- **BaseTest:** Handles browser setup and teardown.
- **DriverManager:** Manages WebDriver initialization and closing.
- **Pages:** Stores page elements and reusable page actions.
- **Tests:** Contains automated test scenarios.
- **ExtentManager:** Configures the ExtentReports instance.
- **ExtentTestListener:** Records test execution results.

### Failed Test Cases – Investigation

Two automated test cases were marked as Failed during test execution:

| Test Case | Module | Status | Observed Issue |
|---|---|---|---|
| Edit Employee | PIM | Failed | TimeoutException occurred while locating the employee search field during page navigation. |
| Delete Employee | PIM | Failed | The employee was not reliably verified as removed from the employee list after the deletion operation. |

**Investigation Notes:**

- The Edit Employee test encountered a page navigation and element identification issue.
- The Delete Employee test required more reliable employee-specific selection and post-deletion verification.
- These failures were treated as automation-related issues requiring further investigation. No confirmed application defects were established based on these failures alone.

## How to Run the Tests

1. Clone the repository.
2. Open the project in IntelliJ IDEA.
3. Make sure the Maven dependencies are downloaded.
4. Open `testng.xml`.
5. Right-click and select **Run 'testng.xml'**.
6. After test execution, open `reports/ExtentReport.html` in a browser to review the results.
